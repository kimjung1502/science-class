## 1. 물리 모델 — **가장 중요한 설계 결정**

### 1.1 "P·V·T 슬라이더 3개"는 만들면 안 된다

요청은 "압력·부피·온도 **각각을** 조절"이지만, 기체 양 `n`이 고정이면
`PV = nRT`가 **구속조건**이라 P·V·T 중 **독립변수는 2개뿐**입니다.
슬라이더 3개를 독립으로 두면 학생이 곧바로 상태방정식을 위반하는 상태
(예: P·V·T를 전부 2배)를 만들 수 있고, 그 순간 화면은 **물리적으로 존재할 수 없는 기체**를 보여줍니다.
이 단원의 학습 목표가 정확히 "세 변수가 서로 묶여 있다"는 것이므로, 이건 치명적입니다.

**대신 채택: 조작 모드(mode) 3종 + 반응 변수**
학생은 **"무엇을 고정하고 무엇을 밀지"**를 고르고, 나머지 하나는 **시뮬레이션이 스스로 반응**합니다.
결과적으로 학생은 세 변수를 모두 조절해 보지만, 매 순간 상태는 물리적으로 정합합니다.

| 모드 | 고정 | 학생이 조절 | 반응(계산) | 대응 법칙 | 실험 장치 은유 |
|---|---|---|---|---|---|
| **등온** (③) | T | **P** — 피스톤 위 추 얹기/빼기 | **V** (피스톤이 내려옴/올라감) | 보일 | 온도조 안 실린더 |
| **등압** (④) | P (추 고정) | **T** — 가열/냉각 | **V** (피스톤 자유 이동) | 샤를 | 자유 피스톤 |
| **등적** (⑤) | V (피스톤 **잠금**) | **T** — 가열/냉각 | **P** (충돌 세짐) | 게이뤼삭 | 고정된 강철 용기 |
| **입자수** (⑥) | P, T | **n** — 입자 주입/제거 | **V** | 아보가드로 | 펌프 |

- 모드 전환은 **탭 UI**가 아니라 **단계 진행 자체**로 자연스럽게 바뀜(③④⑤가 각각 한 모드).
- ⑥ 통합 단계에서만 **자유 모드**를 열어 네 조작을 한 화면에서 다 써보게 함.
- 화면에 **항상 "지금 고정된 것"을 라벨(🔒 온도 고정 300 K)** 로 크게 표시 — 통제변인 개념도 같이 학습.

### 1.2 입자 운동 엔진

- **2D 캔버스**, 실린더 = 세로 직사각형, 위쪽에 **피스톤(수평 막대)**. 입자는 원.
- **물리 좌표계는 고정 논리 좌표(반응형과 분리)**: 모든 물리(입자 위치·속도, `W`·`H`, 충격량, 픽셀↔L 환산, 해석적 보정 상수)는 **고정 논리 좌표계 `W₀×H₀ = 320×420`(논리 단위)**에서 계산. 반응형 캔버스 크기(§2.1의 280×360·저높이 동적 크기)와 `devicePixelRatio`는 **렌더 변환(scale)에만 적용** — 창 크기 변경·회전(resize/orientation)에도 물리 상태·측정값·보정 상수는 전혀 변하지 않음(기기·회전별로 `P_측정`이 달라지는 것 원천 차단).
- **입자 간 충돌은 계산하지 않음** — 입자는 서로 그냥 **통과하는 비상호작용 점입자**로 근사. 이유 두 가지, 둘 다 이 단원에 유리:
  1. **이상기체 가정과 부합하는 근사** — "분자 자체 부피 없음 · 분자 사이 힘 없음"의 시각화. (입자끼리의 탄성 충돌은 전체 운동량·에너지를 바꾸지 않으므로 생략해도 압력·상태방정식 결론은 동일.) 화면 옆에 이 가정을 명시.
  2. O(N²) 충돌 판정 제거 → 폰·태블릿에서도 60fps.
  - 대신 초기 속도를 **`vx`·`vy` 독립 가우시안 `N(0, σ²)`(σ² ∝ T)로 샘플링** — 2D에서 속력 분포는 맥스웰–볼츠만의 2차원판(레일리 분포)이 됨. 화면 문구는 "빠른 입자·느린 입자가 섞여 있다"로 쓰고, 맥스웰–볼츠만을 명시할 땐 "(2차원판)"을 붙임.
- **완전탄성 충돌은 벽·피스톤에서만**(법선 성분 반전). 이 문서에서 "충돌"은 전부 벽·피스톤 충돌을 가리킴(입자끼리는 통과).
- **온도 ↔ 속력**: `v_rms ∝ √T`. T를 바꾸면 전 입자 속도에 `√(T_new/T_old)` 를 곱함(분포 모양 유지).
  - 단계 ④⑤ 라벨: "온도를 올렸더니 **입자가 빨라졌다**" — **절대온도는 분자의 평균 병진 운동에너지에 비례**("온도 = 에너지" 같은 등식 표현은 쓰지 않음).
- **압력 값은 세 가지를 구분**(코드·저장·화면 전부에서 같은 이름 사용):

  | 기호 | 뜻 | 쓰임 |
  |---|---|---|
  | `P_외부` | 추+대기압이 정하는 입력값 | 등온·등압의 조작값. **표·그래프에 기록** |
  | `P_이론` | `nRT/V` 계산값 | 등적·⑥ 자유 모드의 반응값 **기록**. 계기판 병기 |
  | `P_측정` | 피스톤 면 충돌에서 측정 | "압력=충돌" 체감용 표시. **표·그래프·게이트·평형 판정에는 안 씀**, 스냅샷·JSON에는 **진단용으로만 저장**(§3.1) |

  - 표·그래프·`PV/nT`(R) 계산에는 **정합값만** 기록(등온·등압 = `P_외부`, 등적·⑥ = `P_이론`) — 측정 노이즈가 "P×V 일정" 같은 학습 결론을 흔들면 안 됨. `P_측정`은 정합값 옆에 나란히 띄워 "충돌이 압력을 만든다"를 확인시키는 용도.
- **P_측정은 피스톤 면 한 곳에서만** 잰다: `P_측정 = Σ(피스톤 면 법선 충격량) / (W × 시간창)` — **단위 모델은 2D로 통일: 피스톤 길이 `W`당 힘**(아래 해석적 보정 `P = F/W`와 같은 기준. "단면적"(3D)을 쓰려면 유효 깊이 환산이 따로 필요하므로 쓰지 않음)
  - **초당 충돌 카운터·평균 충격량도 같은 피스톤 면 기준** — 옆벽·바닥까지 합치면 "부피 반 → 빈도 2배"가 성립하지 않음(압축 시 높이만 줄기 때문).
  - 단위 환산을 코드에 명시: 픽셀↔L 스케일 상수, `dt`는 초 단위.
  - **모든 입자는 10개 배치 단위로 생성·관리**(§1.4의 0.25 mol 스텝과 1:1): **최초 40개도 배치 4개로 생성·식별**하고, 각 배치는 맥스웰–볼츠만(2D) 샘플링 후 **정확히** 정규화(배치 평균 속도 0, `⟨v_x²⟩=⟨v_y²⟩=σ²(T)`). (정규화 후에는 엄밀한 독립 가우시안·레일리 표본이 아니라 **모멘트를 정확히 맞춘 근사 표본** — 압력·해석적 보정에 필요한 성질은 평균 0·성분 분산 일치뿐이므로 충분. 분포를 명시할 땐 "2D 맥스웰–볼츠만에서 뽑아 압력 모멘트를 맞춘 표본"으로 한정.) 추가·제거는 항상 배치 단위 — 초기 입자를 제거하는 경우까지 포함해 어떤 n에서도 집단 `⟨v_y²⟩`가 목표값을 유지, 해석적 보정이 그대로 성립(§10의 n 조합 검증 통과 조건).
  - **보정은 해석적으로(측정 기반 금지)**: 픽셀→atm 보정 상수는 **닫힌 식으로 유도** — 2D 운동론에서 피스톤이 받는 **시간평균 총 힘**은 `F = N·m·⟨v_y²⟩ / H`(`H` = 실린더 높이), **압력(2D: 피스톤 단위 길이당 힘)은 `P = F / W = N·m·⟨v_y²⟩ / (W·H)`**(`W` = 피스톤 길이) — 두 값을 혼동하지 말 것. 기본 상태(n=1, T=273 K, V=22.4 L)에서 이 `P`가 1.00 atm이 되도록 상수를 입자 수·속도 분산·픽셀 스케일에서 산출(**픽셀→atm 상수에 `W`가 들어감**). 워밍업 측정으로 보정하면 기본 예시(≈24회/s)에서 1.5 s에 충돌 ~36회뿐이라 **SimBlock마다 보정 상수가 크게 달라짐** — 쓰지 않는다.
  - **표시 노이즈**: 이동평균 창 **2 s**(≈50회 충돌 표본, 상대 요동 대략 ±15% 수준 — 개략치)로 표시. **워밍업 = 창이 차는 2 s** — 그동안 `기록` 버튼 비활성("측정 준비 중…"). 숫자가 튀면 학생이 관계를 못 읽음.
- **평형(정착) 판정 — 결정론 조건만 사용**: **모든 P·V·T·n 조작 시 `P_측정` 누산기(이동평균 창)를 즉시 비움.** **피스톤이 움직이는 모든 모드(등온·등압·n)**는 **피스톤 정착(§1.3 수치 조건 충족) 후 누산기를 다시 비우고 새 2 s 창이 다 찼을 때**, **등적(피스톤 잠금)**은 T 조작 종료 후 2 s(창 충전) 경과 시 기록 허용 — 이전 상태·피스톤 이동 중 충돌이 섞인 `pMeasured`가 데이터 점에 저장되거나 화면에 남는 것 방지(`P_측정`은 판정엔 안 쓰지만 스냅샷에 저장되고 학생이 관찰하는 값이므로 새 평형만 반영해야 함). `P_측정` 값 자체는 **평형 판정에 쓰지 않음**(유한 입자·이동평균의 통계 요동으로 기록 버튼이 불규칙하게 잠길 수 있어서).

### 1.3 피스톤 동역학 (진동 방지)

피스톤을 순수 뉴턴 역학으로 놓으면 **위아래로 계속 출렁**입니다(감쇠가 없으므로). 학생은 값을 못 읽습니다.

- 피스톤은 **준정적(quasi-static) 이완**으로 처리: 목표 위치 `V_eq = nRT/P_외부` 로 **임계감쇠(critically damped)** 접근. **감쇠 파라미터 수치 고정: 시간상수 `τ = 0.05 s`(자연주파수 `ω = 1/τ = 20 s⁻¹`)**. **구현은 폐형식 해가 아니라 ODE 수치 적분**: `d²V/dt² = ω²(V_eq−V) − 2ω·(dV/dt)` 를 물리 시간격 `dt = 1/120 s`(§8.2)로 세미-임플리시트 오일러 적분(ω·dt ≈ 0.17이라 안정).
- **이동 중 재조작 정책(확정)**: 피스톤 이동 중에도 조작 컨트롤을 **막지 않는다**(§1.4 범위 규칙에 의한 비활성화만 예외). 재조작은 **`V_eq`만 바꾸고** 현재 `V`·`dV/dt`는 그대로 이어감 — 속도 리셋·조작 큐잉 없음(ODE 적분이라 위치·속도가 자연히 연속). 참고 수치인 폐형식 `|V−V_eq|/V_eq = A·(1+t/τ)e^(−t/τ)`(`A` = 상태 변화 폭)는 **정지 상태(초기 속도 0)에서 목표를 한 번 바꾼 경우에만 성립하는 해** — 그 조건에서 두 정착 조건 충족까지 `A=1`이면 ≈12.4τ ≈ 0.62 s, 극단 `A=11`(V 60→5 L)이면 ≈15.0τ ≈ 0.75 s — 단, 이는 연속 폐형식 기준이고 **실제 이산 적분(위 세미-임플리시트 오일러, dt=1/120)의 실측 정착은 더 김: `A=1`에서 86 step ≈ 0.72 s, `A=11`에서 106 step ≈ 0.88 s. UX 문구·테스트 기대값은 이산 실측 기준을 쓴다**. **연속 재조작 시에는 이 시간 상한이 보장되지 않음** — UI는 "이동 중…" 표시로 흡수하고, 정착은 경과 시간이 아니라 아래 두 수치 조건으로만 판정(정착 시간 하드코딩 금지).
- **정착 판정·스냅 규칙(수치·순서 고정)**: 임계감쇠는 수학적으로 점근(정확히 도달하지 않음)이므로 시간만으로 판정하지 말 것 — ① `|V − V_eq|/V_eq < 10⁻⁴` **이고** ② `|dV/dt|/V_eq < 10⁻³ s⁻¹`이면 → **`V = V_eq`로 스냅** → **`P_측정` 누산기 재초기화(새 2 s 창 충전 시작, §1.2)** → 창이 차면 `기록` 활성. 데이터 점 스냅샷에는 **스냅된 정확한 평형값**을 저장 — ⑥의 `PV/nT`가 표시 4자리에서 항상 같은 값으로 떨어지는 전제(§3.1 정밀도 규칙).
- 이동 중에는 **"이동 중…"** 표시, 정착 후에만 **데이터 점 기록 허용** → 평형 상태 개념도 자연히 학습.
- **단열 압축 맛보기(감쇠 끄기)는 v1에서 제외.** 현재 모델은 T가 입력값이라 피스톤이 한 일이 내부에너지로 들어가지 않음 — 감쇠만 꺼도 온도는 오르지 않고, 제대로 하려면 움직이는 벽과의 충돌(벽 속도 반영)·피스톤 질량·에너지 보존을 별도 설계하고 T를 입자 평균 운동에너지에서 역산해야 함. 틀린 물리를 보여줄 바엔 뺀다.

### 1.4 단위·기본값·범위

| 양 | 단위 | 기본값 | 범위 | 표시 |
|---|---|---|---|---|
| 압력 P | atm | 1.0 | 1.0 ~ 4.0 | 추 0~6개(1개=+0.5 atm), 기본 1.0 = 대기압+피스톤 무게 |
| 부피 V | L | 22.4 | 5 ~ 60 | 실린더 눈금 |
| 온도 T | K | 273 | 100 ~ 600 | **K와 ℃ 병기**(273 K = 0 ℃) · 조작 = 🔥/❄️ 버튼 **±25 K/회**(길게 누르면 4회/s 반복, 키보드 `←→`도 25 K) · **끝점 스냅**: 다음 스텝이 T 범위를 넘으면 정확히 100/600 K로 스냅(123→100, 598→600), 끝점 도달 후 그 방향 버튼 비활성 — 스냅은 T 범위에만 적용, V·`P_이론` 범위 위반은 아래 범위 정합 규칙대로 비활성 |
| 기체양 n | mol | 1.0 | 0.25 ~ 2.0 | **조작 간격 0.25 mol = 입자 10개(항상 정수)**, 40개 = 1 mol |
| R | L·atm/(mol·K) | 0.0821 | 고정 | ⑥에서 학생이 직접 구함 |

- 기본 상태 `n=1, T=273 K, P=1 atm → V=22.4 L` — **표준상태 22.4 L**가 기본값으로 나오게 해서 교과서와 연결.
- 화면 입자 수는 **n에 비례(40개/mol, 최대 80개)**. 물리 계산의 n과 그림의 입자 수를 **같은 값으로 묶음** — 따로 놀면 안 됨.
- **범위 정합 규칙**: 조작으로 **결과 V가 5~60 L을 벗어나거나, 반응값 `P_이론`이 반응 압력 표시 범위 0.25~4.0 atm을 벗어나게 되면** 그 방향 버튼을 비활성화하고 사유 배지를 표시("V가 60 L을 넘어요" / "P가 4 atm을 넘어요"). ⑥ 자유 모드도 동일 — **모드 전환·조작마다 V와 `P_이론`을 함께 검사**해 조절 변수의 유효 범위를 다시 계산(예: n=2, T=100 K, P=3 atm으로 V≈5.5 L을 만든 뒤 등적으로 600 K까지 가열하면 P≈18 atm — 이런 조작은 도중에 차단). **V를 조용히 클램프하는 것은 금지**(PV=nRT 위반 상태가 화면에 생김). 표의 P 1.0~4.0은 **외부압력 입력 범위**, 0.25~4.0은 **반응값 표시(눈금) 범위**.
  - 검산: 등온(T=273, n=1) P 1→4 atm ⇒ V 22.4→5.6 L ✓ / 등압(P=1) T 100→600 K ⇒ V 8.2→49.3 L ✓ / 등적(V=22.4) T 100→600 K ⇒ P 0.37→2.20 atm(반응값, 표시 범위 안) ✓ / n 모드(P=1, T=273) n 0.25→2 ⇒ V 5.6→44.8 L ✓

### 1.5 절대영도 — ④의 하이라이트

샤를 탐구(④)에서 **V–T 그래프의 x축을 ℃ ↔ K 토글**로 둡니다.
- ℃로 그리면 직선이 **원점을 안 지나고** x절편이 **−273 ℃**.
- K로 바꾸면 **원점을 지나는 정비례**.
- → "왜 절대온도를 쓰는가"를 학생이 그래프에서 스스로 발견. 이 토글이 ④의 통과 조건 중 하나.

### 2.1 iframe 높이 제약 (실측 반영)

`단원-상세.html:204` → iframe 높이는 **`min(80vh, 760px)`로 고정**되고 **내부 스크롤**입니다.

- **가로·저높이(landscape) 대응**: 부모 뷰포트가 640×360이면 iframe 내부 높이는 `80vh` ≈ **288px** — 세로형 고정 크기 캔버스는 물리적으로 못 들어감. **내부 높이 ≤ 470px이면 2열 가로 레이아웃으로 전환**(전환점 근거: 1열의 최소 소요 높이 = 캔버스 360 + 터치 컨트롤 44 + 여백 24 + 진행 띠 ≈ 470px — 420px으로 두면 1열 스스로 동시 표시 조건을 못 지킴): 왼쪽 캔버스(높이 = 내부 높이 − 진행 띠, **최소 180px까지 축소** 허용, 실린더 비율 유지), 오른쪽에 컨트롤+계기판 칩을 세로 배치, 그래프·표·서술은 아래 스크롤. 내부 높이가 **220px 미만**이면 시뮬레이터 대신 "화면을 세로로 돌리거나 '새 탭에서 크게 보기'를 쓰세요" 배너를 표시(억지로 구겨 넣지 않음 — 이 배너 판정은 JS로, 리사이즈·회전 시 재계산).
- **미디어쿼리는 '비중첩 구간'이 아니라 캐스케이드 우선순위로 구성**: `min-*` 경계와 짝지으면 CSS 길이가 정수가 아니라서(브라우저 줌·% 레이아웃·DPR) `470px < 높이 < 471px` 같은 **1px 공백 구간**이 생긴다 — `min-height`/`min-width` 경계 사용 금지. **전부 `max-*` 조건으로, 같은 특이도에서 선언 순서로 우선순위를 정한다**(뒤 규칙이 앞 규칙이 만지는 레이아웃·캔버스 속성을 **전부 재지정**): ① 기본 = 2열, 캔버스 320×420 → ② `@media (max-height:530px)`: 캔버스 높이 = `내부 높이 − 진행 띠 − 컨트롤 44px − 여백 24px`(최소 300px, 비율 유지, 레이아웃은 2열 그대로) → ③ `@media (max-width:720px)`: 1열 접기(캔버스 280×360, 계기판은 캔버스 위 오버레이 칩) → ④ `@media (max-height:470px)`: 저높이 2열(캔버스 최소 180px 축소). 검산: 800×600(내부 ≈480px) → ②만 매칭(캔버스 축소 2열) / 600px 폭·내부 500px → ②③ 매칭, ③이 뒤라서 1열 / 640×360·800×360(내부 ≈288px) → ②③④ 또는 ②④ 매칭, ④가 맨 뒤라서 저높이 2열 / **소수 px 경계도 공백 없음**: 내부 470.5px는 ②(±③)로, 폭 720.5px는 ①·②로 떨어짐 — 어떤 (폭,높이) 조합에서도 정확히 하나의 유효 레이아웃이 결정되고 "캔버스+핵심 컨트롤 동시 표시"가 성립.

## 3. 데이터 구조 & 저장

### 3.1 localStorage 스키마 (학생별 키 `ideal_gas_v1_<학번>`)

> ⚠️ 이 페이지는 iframe `srcdoc`으로 주입되어 **부모 사이트와 same-origin** — `단원-상세.html`·스펙트럼 페이지, 그리고 **같은 기기의 다른 학생**과 localStorage를 공유합니다.
> 상태 전체를 **학생별 키 하나**에 JSON으로 저장: `ideal_gas_v1_<학번>` (학번 없으면 `ideal_gas_v1_anon`, 교사 미리보기는 `ideal_gas_v1_teacher`).
> **공용 태블릿 대비**: 로드 시 저장된 `student.sid` ≠ 주입된 학번이면 그 데이터를 **절대 자동 복원·병합하지 않고** 자기 키로 새로 시작합니다.

```json
{
  "version": "v1",
  "student": { "name": "", "sid": "", "fromSite": true },
  "updatedAt": "ISO8601",
  "unlockedStep": 1,
  "intro": { "started": false },
  "predict": { "pv": "", "vt": "", "pt": "", "reason": "" },
  "boyle":   { "points": [{"pExternal":1.0,"pTheory":1.0,"pMeasured":0.98,"v":22.4,"t":273,"n":1.0}], "q1": "", "q2": "", "inverseToggled": false },
  "charles": { "points": [], "axisToggled": false, "intercept": "", "relation": "" },
  "gaylussac": { "points": [], "relation": "" },
  "combine": { "points": [], "rAnswer": "" },
  "assess":  { "a1": "", "a2": "", "a3": "" },
  "aiCheck": { "boyle.q1": {"status":"ok","reason":"","textHash":"…"} },
  "exportedAt": null,
  "exportedHash": null
}
```

- **데이터 점은 기록 시점의 전체 스냅샷** `{pExternal, pTheory, pMeasured, v, t, n}` — 표·그래프·`PV/nT` 계산에 어느 열을 쓰는지는 §1.2 정합값 규칙(등온·등압 = `pExternal`, 등적·⑥ = `pTheory`)을 따름.
- **정밀도 규칙**: 물리 상태·데이터 점은 **내부 배정밀도 그대로 저장**(저장 시 반올림 금지), 반올림은 **표시할 때만**(P·V·T 소수 1~2자리, `PV/nT`는 소수 4자리). "서로 다른 점" 판정(§6)은 내부값 기준 **독립변수 상대차 ≥ 1%**. 이래야 ⑥의 `PV/nT` 열이 모든 점에서 표시 자리수 안에서 같은 값(0.0821)으로 떨어짐 — 위 예시 JSON의 수치는 읽기 좋게 반올림해 적은 것.
- `aiCheck[key].status`는 `'ok' | 'fail' | 'unavailable'` — §8.4 실패 정책 참조. 게이트 판정 필드 대응은 §6 표 참조. **`aiCheck[key].textHash` = 판정 당시 서버로 보낸 텍스트의 해시** — §8.4의 낡은 판정 방지, 그리고 아래 재평가의 "이 판정이 현재 답에 대한 것인가" 대조에 사용(입력 수정 시 그 key의 `aiCheck`를 지우는 규칙은 §8.4와 동일).
- **자동저장**: 값 변경 시 디바운스(400 ms) 저장. 새로고침하면 **재계산된 잠금 단계**(아래 재평가 규칙)까지 전부 펼쳐 복원.
- **`unlockedStep`은 신뢰하지 않음**: 로드 시 저장값과 무관하게 **①부터 §6 게이트를 순서대로 재평가**해 "연속으로 충족된 마지막 단계 + 1"(상한 6)로 재계산 — ①의 게이트는 `intro.started`(시작하기 클릭 시 true 저장)라서 새 상태가 ②로 건너뛰지 않음. 재계산값이 저장값과 다르면 재계산값을 채택하고 **미완료 단계부터 편집 가능** 상태로 펼침 — localStorage에서 `unlockedStep`만 고쳐 게이트를 우회하거나, 불일치 데이터가 읽기 전용으로 굳어 수정 불가가 되는 것 방지. (`unlockedStep` 필드는 표시용 캐시일 뿐.)
- **재평가에는 AI 게이트도 포함**(새로고침 우회 차단): `AI_CHECK=true && REQUIRE_AI_PASS=true`일 때 ②~⑤ 각 단계는 내용 조건에 더해 **그 단계의 AI 대상 키(§8.4) 전부가 현재 텍스트의 해시와 일치하는 종결 상태 `ok` 또는 `unavailable`**이어야 충족. `fail`(해시 일치)·미검수·판정 진행 중·해시 불일치는 **미충족** — 재평가가 그 단계에서 멈추고, 학생이 `다음`을 누르면 §6 배선대로 재검수가 돈다(통신 실패는 여전히 `unavailable`로 통과 — fail-open 유지). `REQUIRE_AI_PASS=false`(기본값)면 AI는 재평가 조건에 들어가지 않음(기존 동작 그대로).
- **로드 검증**: `JSON.parse` try/catch + 스키마 검사 — `version === 'v1'`, 필드 타입(배열/문자열/불리언). **`unlockedStep`은 손상 판정에서 제외** — 신뢰하지 않는 캐시이므로 값이 무엇이든 무시하고 아래 재평가로 재계산(1~6으로 클램프). 수치 검사는 **정합값만 물리 범위로**(`pExternal`·`pTheory`·`v`·`t`·`n`은 §1.4 범위 안) — **`pMeasured`는 통계 측정값이라 순간적으로 범위를 넘은 채 기록될 수 있으므로 유한한 비음수(또는 `null`)인지만 검사**(정상 데이터가 손상본으로 오판돼 전체 초기화되는 것 방지). 하나라도 실패하면 손상본을 `ideal_gas_v1_<학번>_bak`으로 1회 보존하고 **안전 기본값으로 새로 시작**(손상 데이터로 인한 크래시·게이트 우회 방지). `version`이 다른 값이면 마이그레이션 훅 자리(v1 시점에는 리셋 처리).
- 사진 업로드가 없으므로 **스펙트럼 기획서**(`실험 수업/1학기/통합과학1/2단원/스펙트럼_관찰_실험_페이지_기획서_v1.6.md`) §3.3의 용량 fallback은 **불필요** — 데이터가 가벼움.
- 모든 저장은 try/catch. 실패 시 상단바에 `저장 실패 — 내보내기로 백업` 표시.
- **초기화**: 확인 절차 후 **현재 학생의 키만** 삭제(다른 학생·다른 페이지 키는 건드리지 않음).

### 3.2 학생 정보 자동 주입

```js
const S = window.__SITE_STUDENT__ || null;
// S = { name: "김민수", sid: "20900", isAdmin: false }
```
- `S.name`·`S.sid`가 있으면 → 상단 칩에 `20900 · 김민수`, **①의 이름·학번 입력 UI 자체를 안 그림**.
- `S.isAdmin === true` → **교사 미리보기 모드**: 상단에 `교사 미리보기` 배지, **모든 게이트 판정 함수에 명시적 `isAdmin` 우회 분기**를 넣어 전 단계 통과. (참고: 스펙트럼 페이지 커밋 `875e002`는 **사진 필수·AI 검수만** 우회하고 데이터·서술 게이트는 그대로 둠 — 이 페이지는 그보다 넓게 전부 우회. "동일 정책"이 아니라 **확장**임.)
- `S`가 아예 없음(파일 직접 열기 등) → `로그인 정보 없음` 경고 + 이름·학번 수동 입력 fallback.
- **저장 키 결정(로드 시 1회, §3.1)**: `isAdmin` → `_teacher` / `S.sid` 있음 → `_<학번>` / 그 외 → `_anon`.
  - **수동 학번 입력 시 이관(트랜잭션 순서 고정)**: `_anon`으로 진행하다 학번을 입력하면 — ① 대상 키 `_<학번>`을 §3.1 로드 검증으로 읽음(손상이면 `_bak` 보존 후 '빈 키'로 취급). ② **대상이 비어 있으면**: 메모리 상태의 `student.sid/name`을 먼저 갱신 → 대상 키에 저장 → **다시 읽어 저장 성공을 확인** → **활성 저장 키를 `_<학번>`으로 교체**(이후 자동저장은 대상 키에만 씀) → 마지막에 `_anon` 삭제. 중간에 실패하면 `_anon`을 지우지 않고 활성 키도 바꾸지 않음(재시도 가능, 데이터가 두 키로 갈라지는 상태 금지). ③ **대상에 유효 데이터가 있으면** 덮어쓰지 않고 "이 학번의 저장 데이터가 이미 있어요 — 이어하기 / 새로 시작" 선택지: **이어하기** = 대상 데이터를 로드(§3.1 로드 검증 + 게이트 재평가 포함)하고 활성 키를 `_<학번>`으로 교체 — 현재 anon 데이터는 **버려짐을 경고 문구로 고지**하고 `_anon`은 삭제하지 않고 그대로 둠 / **새로 시작** = `student.sid/name`만 채운 새 기본 상태를 대상 키에 저장(기존 대상 데이터는 이 명시적 선택으로 덮어씀)하고 활성 키 교체, `_anon`은 그대로 둠. 어느 경로든 **이관 후 자동저장 대상은 활성 키 하나뿐**(`_anon` 재생성 금지).
  - **부분 정보**: `sid`만 있고 이름이 비면 키는 `_<학번>` + 이름만 수동 입력. 이름만 있고 `sid`가 비면 `_anon` 취급 + 학번 수동 입력(위 이관 규칙 적용).

### 3.3 내보내기(JSON)

- `결과 내보내기(JSON)` → 파일명 `이상기체_{학번}_{이름}_{YYYYMMDD}.json`
- 수집한 데이터 점(보일/샤를/게이뤼삭/입자수 전부) + 서술 응답 + AI 검수 결과 포함 → 세특 근거.
- **내보내기 버튼은 ⑥의 나머지 완료 조건(R·평가 3문항·n 탐구)이 모두 충족된 뒤에만 활성화** — 빈 답으로 먼저 내보내는 순서 역전 방지.
- **내보내기 시도 = ⑥의 AI 검수 트리거**(⑥에는 '다음' 버튼이 없으므로): 버튼을 누르면 아직 미검수인 키(`assess.a1~a3` 등)를 검수 요청. **`AI_CHECK=true`면 `REQUIRE_AI_PASS`와 무관하게 모든 대상 키가 종결 상태(`ok`/`fail`/`unavailable`)가 된 뒤에 실제 다운로드**("확인 중…" 표시, 총 대기 상한 16 s — 넘으면 `unavailable`로 종결하고 진행) — 즉시 다운로드하면 직후 도착하는 `aiCheck` 변경으로 해시가 바로 무효화되기 때문. **`REQUIRE_AI_PASS`는 `fail` 항목이 있을 때 다운로드를 차단할지(true)·경고만 하고 내보낼지(false)에만 적용.** `AI_CHECK=false`면 검수 없이 즉시 다운로드.
- **낡은 내보내기 방지**: 내보내는 순간 **내보내기 payload 전체를 정규 직렬화한 해시**를 `exportedHash`에 저장 — 정규화 규칙을 결정적으로: 키 정렬 + **해시 입력 제외 필드를 명시적 목록으로 고정: `updatedAt`·`unlockedStep`·`exportedAt`·`exportedHash`**(그 외 의미 필드는 전부 포함. `updatedAt`을 포함하면 내보내기 메타 저장 직후 해시가 즉시 불일치하는 자기모순 발생). 이후 데이터 점·서술·`aiCheck` 어느 것이든 바뀌어 해시가 불일치하면 `exportedAt`을 즉시 `null`로 되돌리고 "내용을 수정했어요 — 다시 내보내야 완료돼요" 표시(§6 완료 판정도 함께 풀림).
- **인쇄/PDF 보기**도 제공(그래프는 캔버스 → `toDataURL()`로 이미지 삽입).

- **이상기체 가정 3줄**(입자 자체 부피 무시 / 입자 사이 힘 무시 — 그래서 이 화면에선 입자끼리 그냥 통과 / **벽·피스톤과의** 충돌은 완전탄성)을 `더 자세히 ▾`로 접어 둠.
- **저장**: `intro.started` — `시작하기` 클릭 시 true(§3.1 재평가에서 ①의 게이트로 사용).
- **잠금**: `시작하기` 클릭뿐(다른 조건 없음. 학생 정보는 자동 주입).

- **잠금**: 3문항 모두 선택 + 이유 서술(`trim()` 비어있지 않음).

### ③ 탐구 1 · 등온 — 압력과 부피 (보일)

```
│ STEP 03 · 등온 탐구        🔒 온도 고정 273 K │
│ ┌───────────┬────────────────┐            │
│ │ [실린더]    │ P  1.00 atm     │            │
│ │  ▓▓ 피스톤  │ V  22.4 L       │            │
│ │  · ·  ·    │ T  273 K (0 ℃)  │            │
│ │  ·  ·   ·  │ n  1.00 mol     │            │
│ │  · ·  ·  · │ ─────────────  │            │
│ │            │ 충돌 24회/s      │            │
│ │            │ 평균충격 1.0     │            │
│ └───────────┴────────────────┘            │
│  추 [ − ] ▓▓ [ + ]   P = 1.00 atm          │
│  [● 지금 상태를 표에 기록]                    │
│  ┌ 표 ─────────┬ [P–V 그래프] ─┐            │
│  │ P    V   P×V │   ·           │            │
│  │ 1.0 22.4 22.4│      ·        │            │
│  │ 2.0 11.2 22.4│         · ·   │            │
│  └──────────────┴──────────────┘            │
│  [ 1/V 로 보기 ] ← 토글                      │
│  Q1. 압력을 2배 하면 부피는? [        ]      │
│  Q2. P×V 열의 값이 어떻게 되지? [        ]   │
```
- **조작**: 추 `+`/`−` 로 P만 변경. 피스톤이 준정적으로 내려가고 **입자는 더 좁은 공간에서 피스톤에 더 자주 부딪힘** → 충돌 횟수 카운터(피스톤 면 기준, §1.2)가 올라가는 게 눈에 보임.
- **관찰 포인트(화면 문구)**: "부피를 반으로 줄이면 → 피스톤까지 갔다 오는 거리가 반 → **피스톤 충돌 빈도 2배** → 압력 2배. 입자 **속력은 그대로**(온도 안 변했으니까)."
- **표 자동 채움**: `기록` 버튼을 누를 때만 행 추가(피스톤 정착 후에만 활성).
  - `P×V` 열이 **자동 계산**되어 항상 ~22.4로 일정 → 학생이 직접 발견.
- **그래프**: P–V 쌍곡선. `1/V 로 보기` 토글하면 **직선**이 됨(반비례의 시각적 증명).
- **저장**: `boyle.points[]`, `boyle.q1/q2`, `boyle.inverseToggled`
- **잠금**: **P가 서로 다른** 데이터 점 4개 이상(최대 P ≥ 최소 P × 2) + Q1·Q2 서술(trim) + `1/V` 토글 1회 이상. 기본 상태의 점도 학생이 직접 `기록`을 눌러야 카운트(자동 삽입 없음).

- **조작**: 가열/냉각 버튼(**±25 K/회**, 길게 4회/s 반복 — §1.4)으로 T만 변경. 입자가 **빨라지고**, 피스톤을 더 세게 밀어 올려 부피가 커짐. (게이트의 "폭 ≥150 K"는 한 방향 6회 조작이면 충족)
- **관찰 포인트**: "압력이 고정이니 **평균 압력(꾸준히 미는 힘)**은 같아야 해. 입자가 빨라져서 **한 번 부딪힐 때의 충격**은 커졌으니, **공간을 넓혀 충돌 빈도를 낮춰야** 균형이 맞아." → 정성적 설명을 화면이 유도. (같은 낱말 "세기"를 평균 압력과 1회 충격 두 뜻으로 겹쳐 쓰지 않기 — ⑤의 "빈도·세기" 구분과 용어 통일)
- **하이라이트(§1.5)**: x축 ℃↔K 토글로 **−273 ℃** 발견 → 절대영도 도입.
  - 절편 입력칸은 **−273 ± 5** 허용. 맞히면 "이 온도에서 입자 운동이 멈춘다고 외삽한 값 = **절대영도**" 피드백.
  - 화면 경고: "실제로는 그 전에 액체가 되니까 **외삽**이야."(이상기체의 한계 — ⑥에서 다시 언급)
- **저장**: `charles.points[]`, `axisToggled`, `intercept`, `relation`
- **잠금**: **T가 서로 다른** 점 4개 이상(범위 폭 ≥ 150 K) + **K 축 토글 사용** + 절편 정답(로컬 판정 −273±5, AI 안 보냄) + 서술.

- **`PV/nT` 열이 자동 계산**되어 앞 세 탐구의 모든 점에서 **같은 값 0.0821**이 나오는 걸 학생이 표에서 확인 → 상태방정식을 **데이터에서 귀납**. (표의 P는 §1.2 정합값 열 — 그래서 정확히 일정하게 나옴)

- **입자 주입 모드(n)**: 펌프로 입자를 넣으면 부피가 비례해 늘어남(아보가드로). **조작은 0.25 mol(=입자 10개) 단위의 이산 스텝** — 화면 입자 수가 항상 정수로 40개/mol과 정확히 일치(§1.4). **`기록` 버튼으로 다른 탐구와 같은 스냅샷 형식의 점을 `combine.points[]`에 저장**하고 통합 표·JSON 내보내기에 포함 — 앞 세 탐구는 전부 `n=1`이라 이 점들이 없으면 표에서 `n`의 역할을 데이터로 확인할 수 없음. **서로 다른 n 값 2개 이상**(이산 스텝이라 자동으로 ≥0.25 mol 차이) 기록해야 충족. `nExplored`는 **필드로 저장하지 않고 판정할 때마다 `combine.points`에서 재계산**(낡은/위조 플래그 방지). **필수 활동**(완료 게이트, §6).
- **이상기체의 한계** `더 자세히 ▾`: 아주 낮은 온도·아주 높은 압력에서는 분자 부피와 인력을 무시할 수 없어 어긋남. (④의 절편 외삽 경고와 연결)
- **형성평가 서술 3문항**
  1. 주사기 끝을 막고 누르면 왜 잘 안 눌리는가? (보일 + 입자 충돌로 설명)
  2. 여름에 자전거 타이어가 터질 수 있는 까닭은? (등적 + 게이뤼삭)
  3. 온도를 올렸을 때 압력이 커지는 이유를 **충돌 빈도·세기** 두 낱말을 써서 설명하기
- **저장**: `combine.points[]/rAnswer`, `assess.a1~a3`, `exportedAt`, `exportedHash`

## 8. 접근성 · 성능 · 안정성

### 8.1 모션 (`prefers-reduced-motion`)

시뮬레이션이 **학습 내용 그 자체**라 완전히 끌 수는 없습니다. 대신:
- `prefers-reduced-motion` 감지 시 → **자동 시작 안 함**, 큰 `▶ 시뮬레이션 시작` 버튼을 먼저 보여줌.
- 항상 **⏸ 일시정지 / 속도 0.5× 1× 2×** 컨트롤 제공.
- 단계 전환 스크롤·플래시 등 **장식성 애니메이션은 전부 끔**.

### 8.2 성능

- `requestAnimationFrame` 1개 루프. **화면 밖 캔버스는 `IntersectionObserver`로 정지** — ①③④⑤⑥ 캔버스가 동시에 5개 돌면 저사양 태블릿이 죽습니다. 누적 스크롤이라 **반드시 필요**.
  - **정지 중 기록 금지**: 화면 밖·탭 백그라운드에서는 해당 SimBlock의 `기록` 버튼 비활성("시뮬레이션이 보일 때만 기록") — 멈춰 있던 낡은 `P_측정`이 기록되는 것 방지.
  - **복귀 정책**: `visibilitychange`·재교차 시 물리 타임스탬프를 **리셋**(멈춘 시간을 따라잡지 않음) + `P_측정` 이동평균 창을 비움. 기록 재활성 시점은 **피스톤 상태로 분기** — 이미 **정착 상태**로 복귀했으면 복귀 시점부터 2 s 워밍업 후 재활성, **이동 중**(복귀 후 보존된 `V`·`dV/dt`로 ODE 이동이 이어짐)이면 §1.3 순서(정착 → 누산기 재초기화 → 새 2 s 창 완충) 후 재활성 — §1.2 규칙과 동일.
- 물리는 고정 시간刻(`dt = 1/120 s`) 누적 적분, 렌더는 rAF — 프레임 드랍 시에도 물리가 일정. **프레임당 물리 substep 상한 8** — 초과 누적분은 버림(장시간 정지 후 프리징 방지, 위 복귀 리셋과 한 세트).
- 입자 ≤80개, 입자 간 충돌 없음 → O(N).
- `devicePixelRatio` 반영해 캔버스 선명하게(단 최대 2배로 클램프).

### 9.4 보안 전제(신뢰 모델) — 알고 유지하는 리스크

- 현재 구조는 `sandbox` 없는 same-origin `srcdoc` — **업로드된 HTML이 부모 사이트의 DOM·localStorage·전역 JS에 그대로 접근**할 수 있고, `새 탭에서 크게 보기`(`openHtmlMaterial`, `단원-상세.html:230`)도 same-origin Blob 문서로 이동하므로 동일합니다.
- 이 사이트의 `html` 자료 업로드는 **교사(관리자) 전용**이므로 실험 페이지는 "관리자가 배포하는 코드"로 취급합니다(학생·외부 업로드 경로 없음). **이 전제를 깨는 변경(업로드 권한 확대 등)을 하려면 아래 후속 과제가 선행 조건.**
- **후속 과제(부모 페이지 수정, 이 기획서 범위 밖)**: iframe `sandbox`(단, `allow-same-origin` 제외) + 학생정보·저장·내보내기를 검증된 `postMessage` 브리지로 전환, 새 탭은 `noopener` + 사용 후 `URL.revokeObjectURL`. 전환하면 이 문서 §3.1의 localStorage 직접 접근 설계도 함께 바꿔야 함.
- **배포 선행 조건(전제 검증)**: "관리자 전용 업로드"가 UI 숨김이 아니라 **서버에서 강제**되는지 확인할 것 — `materials` 테이블 INSERT/UPDATE와 `materials` 스토리지 버킷 쓰기를 **학생 세션(비관리자)으로 시도해 거부되는지**(RLS/스토리지 정책) 실측 테스트. 현재 리포에는 이 정책을 보장하는 근거 코드가 없어 전제가 **미검증** 상태. **검증에 실패하면 위 후속 과제(sandbox+postMessage 전환)를 후속이 아니라 이 페이지 배포의 선행 조건으로 승격한다.**

## 10. 제작 순서 (권장)

1. **물리 엔진 코어**(입자·벽 충돌·압력 측정·피스톤 이완) — 단독 테스트 페이지로 먼저 검증
   - 검증 기준(결정론): 등온에서 `P×V` 가 ±3% 안에서 일정, 등적에서 `P/T` 가 ±3% 안에서 일정
   - 검증 기준(충돌 측정 — `P_측정`이 잘못 구현돼도 위 결정론 검사는 통과하므로 별도 필요): 서로 다른 P·V·T·n 조합 **6개 이상**에서 `P_측정/P_이론` = **1.00 ± 5%**. 단, **단일 10 s 실행은 요동이 허용오차보다 커서 판정 불가**이고, **같은 seed 재실행은 같은 궤적을 복제하므로 표본을 늘리지 못함**. 판정 절차(확정): **각 조합마다** — ① **고정 seed 8개(코드에 목록 명시)**를 각각 워밍업 2 s 제외 후 **측정 25 s** 실행. **N ≥ 2,050회는 조합마다** 요구(그 조합의 8개 seed 합산 피스톤 충돌 수 — 기본 상태 ≈24회/s면 8×25 s ≈ 4,800회로 충족, 충돌이 드문 조합은 측정 구간을 연장해 채움). ② **독립 표본 단위는 seed**(seed당 비율 1개): `r_i = P̂_측정(그 seed 측정 구간 전체의 피스톤 충격량 합 / (W × 측정 시간)) / P_이론`. seed 내부의 비중첩 시간창은 **표본 수를 늘리는 데 쓰지 않음**(입자별 주기 충돌로 창끼리 상관 — 창은 워밍업 제외·정상성 확인용). ③ 8개 `r_i`의 평균 `r̄`·표본표준편차 `s`로 **95% t-신뢰구간(자유도 7): `r̄ ± 2.365·s/√8`** 산출. ④ **합격 = `|r̄ − 1| ≤ 0.05` 이고 CI가 1.00을 포함**. CI 반폭이 0.05를 넘으면 합격/불합격 판정을 내리지 말고 seed당 측정 구간을 늘려 재판정. (독립 Poisson 근사의 상대 표준편차 `√(4/(πN))` — N=2,050이면 2σ ≈ 4.98% — 는 **측정 시간 산정용 개략치**로만 쓰고, 합격 판정은 위 실측 t-CI로만 한다.) / 등온 압축 시 **충돌 빈도만 ↑(평균 충격 불변)** / 등적 가열 시 **빈도·평균 충격 둘 다 ↑** — 방향까지 확인
2. 계기판 + 그래프 컴포넌트(재사용: `SimBlock(mode)` 하나로 ③④⑤⑥ 전부 커버)
3. 누적 스크롤 셸 + 게이팅 + localStorage
4. ①②③ 조립 → 확인 → ④⑤⑥
5. AI 검수 연결(§8.4 Edge Function 수정 **먼저**)
6. 업로드 → 실제 `단원-상세.html` 아코디언 안에서 **iframe 실측 확인**(높이·스크롤·학생정보 주입)

1. **§1.1 모드 방식 동의?** — "슬라이더 3개 독립"이 아니라 "고정 1 + 조절 1 + 반응 1". 이게 이 기획서의 뼈대입니다.
2. 데이터 점 조건 — 서로 다른 값 4개 + 범위 폭(③ 2배, ④⑤ 150 K). 학생에게 과한가?
3. `REQUIRE_AI_PASS` (현재 false = 경고만)
4. §8.4 Edge Function 수정 (A)안 — `contextId` 허용목록 방식으로 진행해도 되는지
5. ⑥ 형성평가 3문항 문구
6. 절대영도 절편 허용 오차 (현재 −273 ± 5)
7. 공용 기기 대응 — 학생별 localStorage 키(§3.1)로 충분한가, 제출 서버 저장까지 필요한가
8. §9.4 신뢰 모델 — "관리자 전용 업로드" 전제를 유지할지, 부모 페이지 sandbox+postMessage 전환을 후속 과제로 올릴지
